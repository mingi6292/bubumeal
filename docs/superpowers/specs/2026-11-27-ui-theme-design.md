# UI 디자인 적용 ("따뜻한 식탁") 설계

날짜: 2026-11-27 · 상태: 승인 대기

표시: **[확정]** 사용자가 이전 세션에서 정한 것 / **[제안]** Claude가 채운 것(승인 때 확인 필요)

## 1. 왜, 무엇을

기능은 거의 다 갖췄지만 화면이 Material 기본 모양(보라색, 시스템 글꼴, 3열 표)이라 쓰기 불편하고 앱다운 느낌이 없다. 목업으로 고른 시안 A "따뜻한 식탁"을 앱 전체에 입힌다.

- 목표: 모든 화면에 같은 색·글꼴·둥근 모서리. 주간 식단표는 휴대폰 세로 화면에서 메뉴 글자가 잘리지 않게 하루 카드 목록으로 바꾼다.
- 하지 않는 것 **[확정]**: 다크 테마, 주간 식단표 외 화면의 배치 변경, 새 기능.
- 실패로 보는 것: 기존 기능(주 이동, 이번 주로, 빈 주 안내, 로딩, 끼니 편집, 접근 상실 안내)이 하나라도 사라지거나 동작이 바뀌는 것.

## 2. 방식 (Approaches)

**[확정]** commonMain에 `BubuMealTheme`(MaterialTheme을 감쌈)을 두고 `App()`이 쓴다. 각 화면은 `MaterialTheme.colorScheme/typography/shapes`만 보므로 색·글꼴·모서리는 테마 하나로 모든 화면에 퍼진다.

검토했던 다른 길(이전 세션에서 버림): 화면마다 색을 직접 지정 — 화면이 늘수록 어긋남. 플랫폼별 테마(`expect`/`actual`) — UI를 Compose로 공유하므로 필요 없음.

## 3. 테마 `ui/theme/`

### 색 **[확정 값 → 제안 매핑]**

`lightColorScheme`에 아래처럼 넣는다. 확정한 6색 외 값은 제안이다.

| 역할 | 값 | 비고 |
|---|---|---|
| background, surface | `#faf4ea` 배경 | 확정 |
| surfaceContainerLowest ~ Highest, surfaceBright | `#fffdf8` 카드 | 제안: 대화상자·카드가 모두 이 색 |
| onBackground, onSurface | `#3d2f25` 글자 | 확정 |
| onSurfaceVariant | `#8a7565` 보조 글자 | 확정 |
| outlineVariant | `#eadfce` 선 | 확정 |
| outline | `#a8937c` | 제안: 목업의 빈 끼니 "+ 메뉴 적기" 색(목업 `--faint`) |
| primary | `#c4552d` 강조 | 확정 |
| onPrimary | `#ffffff` | 제안(목업과 같음) |
| primaryContainer / onPrimaryContainer | `#f7e1d6` / `#3d2f25` | 제안: 옅은 강조 배경 |
| secondary 계열, tertiary 계열 | primary와 같은 값 | 제안: 보라색이 새어 나오지 않게 |
| error 계열 | Material 기본 | 제안 |

참고(바꾸자는 것은 아님): `#c4552d`는 배경 위에서 대비가 약 4.1:1, 흰 글자와는 약 4.5:1이라 아주 작은 글자에서는 읽기 기준(4.5:1)에 살짝 못 미친다. 강조색 글자는 14sp 이상이나 굵게 쓰는 쪽으로 한다 **[제안]**.

### 글꼴 **[확정]**

- SUIT v2.0.5 OTF 4개: Regular(400), Medium(500), SemiBold(600), Bold(700)를 `shared/src/commonMain/composeResources/font/`에 둔다. 파일 이름은 리소스 이름 규칙에 맞게 `suit_regular.otf`처럼 소문자·밑줄로 바꾼다 **[제안]**.
- `Res.font.*`의 `Font()`는 Composable이라 `FontFamily`와 `Typography`를 `@Composable` 함수 안에서 만든다. Material 기본 `Typography()`의 모든 스타일에 `fontFamily = SUIT`만 바꿔 끼우고 크기·굵기는 기본값 유지 **[제안]**.
- OFL 라이선스 전문을 `shared/src/commonMain/composeResources/files/licenses/SUIT-OFL.txt`에 함께 둔다(앱에 글꼴과 같이 들어감). 앱 안 "오픈소스 라이선스" 화면은 이번 범위가 아니다 **[제안]**.

### 모양 **[제안]**

`Shapes(extraSmall=8, small=12, medium=16, large=20, extraLarge=28 dp)`. 하루 카드는 large(20dp, 목업과 같음). 버튼은 Material 기본대로 둥근 알약형.

## 4. 주간 식단표 화면 **[확정 배치]**

```
 내 식단표 ▼                    설정     ← 상단 바(배경색), 제목 누르면 식단표 전환
   ‹      11월 23일 ~ 11월 29일      ›
             ( 이번 주로 )                ← 이번 주가 아닐 때만
 이 주에는 아직 식단이 없어요. …           ← 빈 주일 때만
 ━━━━━━━━━━ (로딩 중일 때 진행 막대)
 ┌──────────────────────────────┐
 │ 11/26 (목)  [오늘]              │  ← 오늘 카드: 강조색 2dp 테두리 + 배지
 │ 아침  누룽지                    │
 │ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
 │ 점심  + 메뉴 적기               │  ← 빈 끼니는 outline 색
 │ ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄ │
 │ 저녁  삼겹살, 파절이, 김치찌개    │  ← 줄 수 제한 없이 줄바꿈
 └──────────────────────────────┘
 (카드 7개, LazyColumn, 간격 10dp)
```

- 상단 제목은 역할 이름 + ▼ (`내 식단표 ▼` / `참여 중인 식단표 ▼`). 지금의 "전환" 버튼을 대신한다. 오른쪽 "설정"은 그대로 **[제안: 동반자도 같은 모양]**.
- 주 이동, 이번 주로, 빈 주 안내, 진행 막대는 목록 **위에 고정**하고 하루 카드만 스크롤한다(목업과 같음) **[제안]**.
- 끼니 한 줄 전체가 누르는 영역(최소 높이 44dp). 누르면 지금처럼 `onCellClick` → 편집 창. 메뉴 글자는 잘라내지 않는다(목업과 같음).
- `hasNoPlan`일 때의 "식단표가 없어요." 문구, 끼니 편집 창, 접근 상실 안내는 그대로(색·글꼴만 테마를 따름).
- `WeeklyScreen`의 매개변수(콜백)는 바꾸지 않는다. 그래서 `AppNavHost`와 `WeeklyViewModel`은 손대지 않는다 **[제안]**.

### 오늘 카드 자동 스크롤 **[제안]**

원칙: "이번 주를 새로 열었을 때"만 오늘 카드로 가고, 사용자가 보던 자리는 빼앗지 않는다.

| 상황 | 스크롤 |
|---|---|
| 화면에 처음 들어옴(로그인·만들기·참여 뒤) | 오늘 카드로 |
| "이번 주로" 누름, 또는 ‹ › 로 이번 주에 돌아옴 | 오늘 카드로 |
| 다른 주로 이동 | 맨 위(월요일)로 |
| 식단표를 전환함(다른 식단표가 됨) | 이번 주면 오늘 카드, 아니면 맨 위 |
| 끼니 저장·삭제, 편집 창 닫기 | 움직이지 않음 |
| 설정·전환 화면에 갔다가 같은 식단표로 돌아옴 | 움직이지 않음 |
| 화면 회전 | 움직이지 않음(보던 위치 유지) |
| 접근 상실 뒤 남은 식단표로 바뀜 | 식단표 전환과 같음 |

구현 방향: 스크롤 기준을 `(식단표 id, 주 시작일)` 짝으로 잡고, 이 짝이 바뀔 때만 한 번 스크롤한다. 마지막으로 스크롤한 짝은 `rememberSaveable`에 둬서 회전이나 다른 화면에서 돌아올 때 다시 스크롤하지 않게 한다. 카드 7개는 로딩 중에도 늘 있으므로 `scrollToItem(오늘 인덱스)`를 바로 해도 된다(애니메이션 없이 바로 이동). 오늘 인덱스 계산(`week.days.indexOf(today)`, 없으면 0)은 순수 함수로 빼서 `commonTest`로 확인한다.

## 5. 다른 화면 **[확정: 색·글꼴·모서리만]**

로그인, 시작, 공유 코드 입력·발급, 식단표 전환, 설정은 코드 배치를 바꾸지 않는다. 테마를 바꾸면 TopAppBar·버튼·대화상자·ListItem 색이 저절로 따라온다. 화면에 색을 직접 적은 곳이 있으면 테마 값으로 바꾼다(지금은 주간 화면 외에 없음).

Android 상태 표시줄: 이미 `enableEdgeToEdge()`를 쓰고 배경이 밝으므로 어두운 아이콘이 나온다. 따로 손대지 않는다 **[제안]**.

## 6. 확인 방법

- `commonTest`: 오늘 인덱스·스크롤 대상 계산 함수. 기존 테스트(`:shared:testAndroidHostTest`)가 모두 통과.
- `:androidApp:assembleDebug` 성공, APK 크기 증가가 글꼴 크기(약 1.4MB) 정도인지 확인.
- 에뮬레이터(사용자가 켜 둔 것)에서 눈으로: 모든 화면 색·글꼴, 오늘 카드 강조, 4장 표의 스크롤 상황, 긴 메뉴 줄바꿈, 접근 상실 안내.
- iOS는 빌드할 수 없다. 공통 코드만 쓰므로 iOS도 같게 보일 것으로 보지만 확인하지 못한다.

## 7. 짓는 사람에게 맡기는 것

카드 안쪽 여백·글자 크기 같은 세부 수치(목업 값을 출발점으로), 테마 파일 나누기, 커밋 단위.
