# 부부밀(BubuMeal) 앱 개발자용 기획 문서

- 문서 기준일: 2026-11-11
- 기준 기획안: 티켓 분할안 v5 (사용자 승인 완료)
- 상태: 기획 확정, **백엔드 구현 진행 중** (엔드포인트와 응답 형식은 아직 확정 전)
- **변경 사항 (v5 이후):** 로그인 방식을 이메일/비밀번호에서 **카카오, 네이버, 구글, 애플 간편 로그인**으로 바꿨습니다. 백엔드 회원/인증 티켓(BUB-11)도 이 기준으로 다시 기획해야 합니다.

> 이 문서는 모바일 앱 개발자가 "무엇을 만드는 서비스이고, 서버가 어떤 규칙으로 동작하는지"를 파악하도록 정리한 것입니다.
> 기획에 명시되지 않은 부분은 9장에 "협의 필요"로 따로 모았습니다. 임의로 가정하지 말고 확인해 주세요.

## 1. 서비스 개요

부부(또는 두 사람)가 함께 쓰는 **주간 식단표 앱**입니다.

- 웹앱으로 먼저 시작하고, 같은 API를 모바일 앱이 그대로 사용할 수 있도록 **API 우선 구조**로 만듭니다.
- 서버는 REST API로 동작하고, 웹 프론트와 모바일 앱은 모두 이 API의 클라이언트입니다.
- API 문서는 서버가 OpenAPI(Swagger)로 자동 생성합니다.

## 2. 용어

| 용어 | 의미 |
|---|---|
| 식단표 | 한 주 단위로 끼니별 메뉴를 적는 공유 문서. 소유자 1명 + 동반자 최대 1명이 함께 씁니다 |
| 소유자 | 식단표를 만든 사람 |
| 동반자 | 공유 코드를 입력해 그 식단표에 참여한 사람 (식단표당 최대 1명) |
| 공유 코드 | 소유자가 발급해 동반자를 초대하는 일회용 코드 |
| 연결 해제 | 동반자가 식단표에서 빠지는 것 |
| 간편 로그인 제공자 | 카카오, 네이버, 구글, 애플. 사용자는 이 중 하나로 로그인합니다 |

식단표는 두 사람이 모여야 만들어지는 것이 아닙니다. **소유자 혼자서도 만들 수 있고**, 동반자는 나중에 추가할 수 있는 선택 사항입니다.

## 3. 사용자 흐름

1. 카카오, 네이버, 구글, 애플 중 하나로 **간편 로그인**합니다. 처음 로그인하면 계정이 자동으로 만들어집니다 (별도 회원가입 화면 없음).
2. 가입한다고 식단표가 자동으로 생기지 않습니다. 로그인한 뒤 **"식단표 만들기"를 직접 실행**해야 합니다.
3. 소유자는 **공유 코드를 발급**해 상대에게 전달합니다.
4. 상대는 간편 로그인한 뒤 **코드를 입력**해 그 식단표의 동반자가 됩니다.
5. 두 사람이 **같은 권한으로** 주간 식단표를 조회/편집합니다.
6. 필요하면 연결을 해제하거나, 소유자가 식단표를 삭제합니다.

## 4. 기능 요구사항

### 4.1 회원/인증 (간편 로그인)

- 지원 제공자: **카카오, 네이버, 구글, 애플**
- 이메일/비밀번호 가입과 로그인은 지원하지 않습니다.
- 로그인 흐름:
  1. 앱이 각 제공자의 SDK(또는 웹 로그인)로 로그인합니다.
  2. 앱은 제공자가 준 토큰(ID 토큰 또는 access 토큰)을 서버로 보냅니다.
  3. 서버가 그 토큰을 제공자 기준으로 검증합니다.
  4. 검증되면 서버가 **서비스 자체의 access 토큰과 refresh 토큰을 발급**합니다.
- 처음 로그인한 사용자는 계정이 **자동 생성**됩니다.
- 사용자는 **제공자 + 제공자의 사용자 고유 ID**로 식별합니다. 이메일은 식별 기준으로 쓰지 않습니다 (제공자에 따라 이메일을 받지 못하거나 가려진 주소가 올 수 있음).
- 토큰 갱신(refresh) API
- 인증이 필요한 API는 서비스 access 토큰을 검증합니다 (쿠키 세션이 아니라 토큰 방식)
- 가입 시 식단표를 자동 생성하지 않습니다
- 참고: 애플 로그인은 iOS에서는 기본 제공 기능으로 처리하지만, Android에는 애플 SDK가 없어서 웹 로그인 방식으로 처리해야 합니다.

### 4.2 식단표 생성·삭제

- **생성:** 로그인한 사용자가 "식단표 만들기"를 호출하면 본인 소유의 식단표가 하나 생깁니다.
- 한 사용자가 소유하는 식단표는 **하나**입니다 (여러 개 소유는 지원하지 않음).
- **삭제:** 소유자만 가능합니다. 동반자가 시도하면 에러입니다.
  - **즉시 하드 삭제**입니다. 식단표, 모든 끼니 데이터, 발급된 공유 코드 기록이 영구 삭제되고 복구할 수 없습니다.
  - 삭제 시점에 동반자가 있었다면, 그 동반자도 즉시 접근을 잃습니다.
  - 삭제 전에 **2차 확인 단계**를 둡니다 (프론트 쪽 UI 책임).

### 4.3 공유 코드와 연결/해제

공유 코드 규칙:

| 항목 | 규칙 |
|---|---|
| 발급 권한 | **소유자만**. 동반자가 발급을 시도하면 에러 |
| 형식 | 영문+숫자 8자리, 혼동되기 쉬운 문자(`0/O`, `1/I`) 제외, 무작위 |
| 유효 시간 | 발급 후 **3시간** |
| 사용 횟수 | **1회용** |
| 동시 유효 코드 | 식단표당 **최대 1개**. 새 코드를 발급하면 이전의 미사용 코드는 즉시 무효 |
| 입력 시도 제한 | 같은 사용자가 **10분 안에 5번 틀리면 15분간** 코드 입력이 차단됨 (응답에 남은 시도 가능 여부 포함) |
| 자기 코드 입력 | 소유자가 자기가 발급한 코드를 입력하면 에러 |

연결:

- 다른 사용자가 코드를 입력하면 그 식단표의 동반자가 됩니다.
- 에러가 되는 경우: 코드 만료, 이미 사용됨, 이미 동반자가 있는 식단표
- 이미 **자기 식단표가 있는 사용자도** 다른 사람의 식단표에 동반자로 참여할 수 있습니다. 이때 자기 식단표는 그대로 유지됩니다.
- 사용자는 접근 가능한 식단표 목록(**본인이 소유한 것 + 현재 동반자로 연결된 것**)을 조회하고, 그 사이를 전환해서 볼 수 있습니다.

연결 해제:

- **소유자가 동반자를 해제**할 수 있고, **동반자 본인이 스스로 나가는 것**도 가능합니다. 결과는 같습니다.
- 해제되면 동반자였던 사람은 그 식단표에 **접근을 완전히 잃습니다 (조회도 불가).**
- 식단표 자체와 데이터는 **삭제·변경 없이 소유자에게 그대로 남습니다.**
- 해제 후에도 소유자는 새 공유 코드를 발급해 다시 동반자를 추가할 수 있습니다.

### 4.4 주간 식단표

- **주 단위** 조회: 7일 x (아침/점심/저녁) 구조
- 끼니별 **메뉴 텍스트**를 생성/수정/삭제할 수 있습니다.
- 소유자와 동반자는 **완전히 같은 권한**으로 편집합니다 (역할 구분 없음).
- 데이터가 없는 주는 **빈 상태로 조회**되고, 끼니를 처음 입력하면 그 주가 자동으로 만들어집니다.

## 5. 앱에서 처리해야 할 예외 상황

기획에서 확정된 에러 상황입니다. 구체적인 에러 코드와 응답 형식은 API 구현 후 OpenAPI 문서에서 확정됩니다.

- 간편 로그인 (로그인 방식 변경에 따라 추가, 세부 처리는 확정 전): 사용자가 로그인 창에서 취소함 / 제공자 토큰 검증 실패 / 제공자 서버 오류나 네트워크 오류
- 공유 코드 입력: 만료됨 / 이미 사용됨 / 이미 동반자가 있음 / 본인 코드 입력 / **시도 제한으로 일시 차단됨(15분)**
- 권한: 동반자가 공유 코드를 발급하거나 식단표를 삭제하려는 경우
- 접근 상실: 연결이 해제되었거나 식단표가 삭제된 뒤 그 식단표에 접근하려는 경우

## 6. API 연동 방식

- REST API, JSON
- 인증: 앱이 간편 로그인으로 받은 제공자 토큰을 서버에 보내면 서버가 서비스 access/refresh 토큰을 발급합니다. 인증이 필요한 요청에는 서비스 access 토큰을 사용합니다.
- API 문서: OpenAPI 3.1 JSON (`/v3/api-docs`)과 Swagger UI (`/swagger-ui.html`)가 서버에서 자동 제공됩니다. 로컬 개발 서버(`localhost:8080`)에서 동작을 확인했습니다.
- 헬스 체크: `/actuator/health`
- 서버 스택(참고): Kotlin + Spring Boot, PostgreSQL, Docker로 실행
- **엔드포인트 경로와 요청/응답 스키마는 아직 없습니다.** 회원/인증(티켓 BUB-11, 간편 로그인으로 재기획 필요), 식단표/공유 코드(BUB-13), 주간 식단표(BUB-15) 구현이 끝나면 OpenAPI 문서가 실제 명세가 됩니다.

## 7. 현재 지원하지 않는 것 (범위 밖)

- 이메일/비밀번호 가입과 로그인
- 레시피, 재료, 사진 첨부
- 캘린더 뷰 (주간 표 형태로만 조회)
- 식단표 템플릿/복사
- 한 사용자의 여러 식단표 소유, 식단표 소유권 이전, 서로 다른 식단표 데이터 병합
- 삭제된 식단표의 복구(휴지통), 삭제 전 데이터 내보내기
- 해제된 동반자의 과거 식단표 조회
- 소유자/동반자 간 권한 차등

## 9. 협의 필요 (기획에 명시되지 않은 부분)

아래는 현재 기획에 **정해진 바가 없어서** 앱 설계에 영향을 줄 수 있는 항목입니다. 필요한 것은 기획에 질문해 확정해야 합니다.

간편 로그인 관련 (로그인 방식 변경으로 새로 생긴 항목):

- 같은 사람이 다른 제공자로 로그인했을 때 계정을 합칠지 (계정 연결), 아니면 별개 계정으로 볼지
- 이메일을 받지 못하거나 애플의 가려진 이메일이 올 때 처리 방식
- 닉네임이나 프로필 사진을 제공자에서 가져와 쓸지
- 회원 탈퇴 기능과 절차 (iOS 앱은 앱 안에서 계정을 삭제할 수 있어야 앱 스토어 심사를 통과함. 애플 로그인 사용자는 탈퇴 시 애플 토큰 해지도 필요)
- 탈퇴한 사용자가 소유자이거나 동반자일 때 식단표 처리
- 각 제공자 개발자 앱 등록(카카오 디벨로퍼스, 네이버 개발자센터, Google Cloud, Apple Developer)과 키 관리 담당

기존 항목:

- access/refresh 토큰의 만료 시간, refresh 토큰이 만료되었을 때의 동작
- 공유 코드 입력 시 대소문자 구분 여부
- 식단표 이름 등 식단표 자체의 속성이 있는지 (현재는 소유자/동반자와 주별 끼니 데이터만 정의됨)
- 한 주의 시작 요일(월요일/일요일)과 시간대 기준
- 끼니 텍스트의 최대 길이
- 동반자가 연결/해제되었을 때 상대방에게 알림이 가는지 (푸시 알림 포함, 현재 계획에 없음)
- 두 사람이 같은 칸을 동시에 편집할 때의 충돌 처리
- 오프라인 사용 지원 여부
- 접근이 끊긴 식단표에 접근했을 때 서버가 돌려주는 응답 형태
